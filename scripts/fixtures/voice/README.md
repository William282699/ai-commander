# 语音输入 V1 · 台架音频 fixture

`ab-voice-input.ts --live` 用的两段命令语音。**入库不是为了省事，是家法**：
判据挂在这两段字节上，它们一变，历史上所有 heard 数字就不可比了。
（`--live` 跑前会先比对 sha256——夹具先自证，见下。）

| 文件 | 原句 | 作用 |
|---|---|---|
| `cmd1.wav` | 战狼点附近的闲置部队，去增援南线前哨 | 主判据。**「战狼点」是玩家自造的标记名**——通用语言模型先验里不存在，只活在本局信封的 `---TAGS---` 里，所以它是"耳朵带着信封听"这条红利的最短证明。消融实测：无信封 0/4、带信封 4/4。 |
| `cmd2.wav` | 派两个步兵班去 El Alamein，剩下的守住烽火台 | 脏样本。中文里夹一个英文地名（I2 的账根），另带一个改名刀的新名「烽火台」。用来盯 N2（音频含糊时模型交付"顺过的意思"而不是逐字原话）。 |

## 出处（可复现，但复现出来的不是同一段字节）

macOS `say` 合成，16kHz 单声道 Int16 WAV：

```bash
say -v Flo "战狼点附近的闲置部队，去增援南线前哨" -o cmd1.aiff
afconvert -f WAVE -d LEI16@16000 -c 1 cmd1.aiff cmd1.wav
```

`say` 的输出跨系统版本会漂，所以**复现命令只作出处记录，不作再生手段**——
判据比的是入库的这两个 sha256。

## 夹具先自证（Fable 立规，2026-08-09）

任何音频 A/B 开跑之前，先证明夹具自己不掉字，否则比较结果一个字不许用。
起因：步 3 冒烟里用合成 `MediaStreamDestination → MediaStreamSource` 假麦做
opus-vs-PCM 对照，而那条往返**自己就掉字**——两臂被同一个夹具伤害，那组数作废。
本目录的自证是**字节级**的：sha256 钉死 + WAV 头断言（16kHz / 单声道 / 16bit），
保证没人在中间悄悄重编码过。
