# 语音输入 V1 · 台架音频 fixture

`ab-voice-input.ts --live` 用的两段命令语音。**入库不是为了省事，是家法**：
判据挂在这两段字节上，它们一变，历史上所有 heard 数字就不可比了。
（`--live` 跑前会先比对 sha256——夹具先自证，见下。）

| 文件 | 臂 | 原句 | 作用 |
|---|---|---|---|
| `cmd1.wav` | 净 | 战狼点附近的闲置部队，去增援南线前哨 | 主判据。**「战狼点」是玩家自造的标记名**——通用语言模型先验里不存在，只活在本局信封的 `---TAGS---` 里，所以它是"耳朵带着信封听"这条红利的最短证明。消融实测：无信封 0/4、带信封 4/4。 |
| `cmd2.wav` | 脏 | 派两个步兵班去 El Alamein，剩下的守住烽火台 | 脏样本一。中文里夹一个英文地名（I2 的账根），另带一个改名刀的新名「烽火台」。★实测它是**归一化**最烈的一格：El Alamein 被换成信封里的「北线前哨」5/7。 |
| `cmd1_cut600.wav` | 脏 | 战狼点附近的闲置部队，去增援南…（尾部 600ms **语音**被机器切掉） | 脏样本二（2026-08-09 分臂重组新增）。复制的是用户手测那个病：松手即拆线 → 尾巴被切 →「…现在怎么办」变成「…现在怎么」。**基准真值由构造保证**：音频里物理上不存在「前哨」那两个音，而信封里写着「南线前哨」——heard 里冒出「前哨」＝模型拿信封补了它没听见的音。 |

### `cmd1_cut600.wav` 的切法（代码入库：`scripts/make-voice-cut-fixture.ts`）

```bash
npx tsx scripts/make-voice-cut-fixture.ts
```

**不是"砍掉最后 600ms"**：cmd1 尾部有 0.513s 的数字静音（`say` 的收尾），
直接砍 600ms 只砍掉 87ms 语音，夹具就是废的。切法＝按 20ms 窗 RMS 找到
**语音结束点**（3.880s），从那里往回切 600ms ⇒ 切点 3.280s。

被咬过一次，留痕：首版按"44 字节标准头"读 WAV，量出来是 0.126s 静音、切点算在
0 秒、**产物是个空文件而脚本一声不吭**。真相是 afconvert 在 fmt 后面插了一个
4044 字节的 `FLLR` 填充块，data 实际起于第 4096 字节。判据要是挂在那个空文件上，
"归一化率 0/7" 会是一个漂亮的假绿。现在读 WAV 一律按 chunk 走。

## 出处（可复现，但复现出来的不是同一段字节）

macOS `say` 合成，16kHz 单声道 Int16 WAV：

```bash
say -v Flo "战狼点附近的闲置部队，去增援南线前哨" -o cmd1.aiff
afconvert -f WAVE -d LEI16@16000 -c 1 cmd1.aiff cmd1.wav
```

`say` 的输出跨系统版本会漂，所以**复现命令只作出处记录，不作再生手段**——
判据比的是入库的这两个 sha256。

## 夹具先自证（Fable 立规，2026-08-09）

任何音频 A/B 开跑之前，先证明夹具自己不掉字，否则比较结果一个字不许用。
起因：步 3 冒烟里用合成 `MediaStreamDestination → MediaStreamSource` 假麦做
opus-vs-PCM 对照，而那条往返**自己就掉字**——两臂被同一个夹具伤害，那组数作废。
本目录的自证是**字节级**的：sha256 钉死 + WAV 头断言（16kHz / 单声道 / 16bit），
保证没人在中间悄悄重编码过。

截断夹具比 sha256 还要多一层——sha 只证"没人动过这个文件"，证不了"这个文件
确实是那段原始音频的纯截断"。所以 `--live` 的 L0 段拿 cmd1.wav **现场重算**：
① 保留的每一个样本与原件**逐样本相同**（纯截断，没重编码没重采样）；
② 切点就是生成脚本算出来的那个（切法与验收 import 同一份代码，漂不了）；
③ 被切掉的 600ms **是语音不是静音**（峰值 RMS 6027 vs 全曲峰值 9559）。
